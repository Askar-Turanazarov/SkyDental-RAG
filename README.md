# SkyDental — лендинг стоматологии в Ташкенте

Одностраничный сайт клиники на **Vite + React + TypeScript**, два языка (RU / UZ), чат-ассистент
с заглушкой под будущий RAG-бэкенд. Внешних картинок и веб-шрифтов нет — вся графика нарисована в SVG.

## Запуск

```bash
npm install
npm run dev       # разработка: http://localhost:5173
npm run build     # проверка типов + сборка в dist/
npm run preview   # просмотр собранной версии
```

`dist/` — статические файлы. Их можно выложить на любой хостинг: Netlify, Vercel, GitHub Pages
или nginx. Пути относительные (`base: './'`), так что сайт работает и из подпапки.

## Структура

```
src/
├── styles/        tokens.css — цвета, шрифты, отступы (светлая и тёмная тема)
│                  base.css — сброс и кнопки · glass.css — стекло · sections.css — секции
├── i18n/          ru.ts, uz.ts — ВСЕ тексты сайта; types.ts — общая форма словаря
├── components/    Header, Hero, Services, About, Faq, Contacts, Footer
│   └── chat/      ChatWidget, useChat, ragClient (точка подключения), mockKnowledge
```

## Как заменить данные клиники

Все тексты, цены, телефоны и адрес лежат в `src/i18n/ru.ts` и `src/i18n/uz.ts`. Меняйте оба
файла. Если добавить ключ в один словарь и забыть про другой, `npm run build` упадёт с
ошибкой — непереведённый текст на сайт не попадёт.

Некоторые данные повторяются вне словарей, их нужно поменять отдельно:

| Что | Где |
| --- | --- |
| Telegram-ссылка | `TELEGRAM_URL` в `components/Contacts.tsx` и ссылка в `components/Footer.tsx` |
| Ссылка на карту | `MAP_URL` в `components/Contacts.tsx` |
| SEO: адрес, телефон, часы | блок JSON-LD и meta-теги в `index.html` |

> Все цифры сейчас — **заглушки**: цены, год открытия, рейтинг. Перед публикацией их нужно
> заменить на реальные.

### Явные заглушки

Три поля намеренно не заполнены правдоподобными значениями — их нельзя перепутать с настоящими,
и на сайте они показаны пунктиром с подсказкой «демо-данные»:

| Поле | Ключ в словарях | Что сделать |
| --- | --- | --- |
| Адрес, конец строки | `contacts.address` | подставить дом и этаж вместо `__` |
| Телефон | `contacts.phone` и `contacts.phoneHref` | видимый номер и цифры для `tel:` |
| Номер лицензии | `footer.license` | номер вместо `__-____` |

`phoneHref` — это отдельный ключ с одними цифрами. Пока он пустой, компонент
`components/PhoneLink.tsx` показывает номер **текстом, а не ссылкой**: иначе `tel:` вёл бы в
никуда. Как только цифры появятся, все четыре места (контакты, подвал, два места в чате)
станут ссылками сами.

Заодно поправьте `MAP_URL` в `components/Contacts.tsx` (сейчас ищет по улице без дома) и блок
JSON-LD в `index.html`.

## Оформление: светлое, тёмное, авто

Переключатель стоит в шапке (на узком экране — в меню под бургером) и имеет три положения:

- **Авто** — по умолчанию, следует системной теме через `prefers-color-scheme`;
- **Светлое** и **Тёмное** — ручное переопределение, запоминается в `localStorage`
  (`skydental.theme`).

Как это устроено: тема резолвится в JS и пишется атрибутом `data-theme` на `<html>`. Поэтому в
CSS ровно **один** блок тёмных токенов — `:root[data-theme='dark']` в `styles/tokens.css`, а не
две копии под media-запросом и под атрибутом. Мерцание при загрузке снимает маленький
синхронный скрипт в `<head>` файла `index.html`: он выставляет тот же атрибут до первой
отрисовки. Если правите ключ хранилища — правьте в обоих местах, скрипт и `theme/ThemeContext.tsx`
должны совпадать.

## База знаний: `content/rag/`

Знания клиники лежат обычным markdown:

```
content/rag/
├── ru/{prices,faq,schedule}.md
└── uz/{prices,faq,schedule}.md
```

Это **единственный источник правды**: демо-бот отвечает по этим файлам, и эти же файлы уйдут
в настоящий RAG-пайплайн. Копий в TypeScript нет специально — иначе данные разъедутся.
Править их может администратор клиники, разработчик для этого не нужен.

Разбор в `components/chat/knowledgeBase.ts` опирается на две структуры, поэтому их стоит
соблюдать при правках:

- `# Заголовок` — название документа, попадает в подпись источника;
- `## Раздел` — один раздел становится одним ответом бота;
- **строка таблицы** — отдельный ответ. Для прайса это важно: иначе все позиции слиплись бы
  в один ответ. Первая колонка — название позиции, она же идёт в подпись источника.

Добавили услугу — дописали строку в таблицу, и бот уже о ней знает. Пересборка не нужна в
dev-режиме, для продакшена — обычный `npm run build`.

Телефон, дом и этаж в `schedule.md` — те же заглушки `__`, что и на сайте: бот не должен
называть номер, которого нет на странице.

## Подключение RAG-бота

Сейчас виджет работает в **демо-режиме**: он отвечает по локальной базе, собранной из текстов
самого сайта (FAQ, услуги, контакты). В панели чата видна плашка «Демо-режим».

Чтобы подключить настоящий бэкенд:

1. Сделайте эндпоинт, который принимает `POST` с JSON:
   ```json
   { "question": "Сколько стоит имплант?", "locale": "ru", "history": [{ "role": "user", "text": "…" }] }
   ```
   и отвечает:
   ```json
   { "answer": "…", "sources": [{ "title": "Прайс 2026", "url": "https://…" }], "found": true }
   ```
   `found: false` или пустой `answer` означает «в материалах ответа нет». Тогда виджет честно
   скажет об этом и предложит позвонить — ничего выдумывать он не будет.
2. Скопируйте `.env.example` в `.env` и укажите `VITE_RAG_ENDPOINT=https://…/chat`.
3. Пересоберите проект. Демо-плашка пропадёт сама.

Вся логика подключения — в `src/components/chat/ragClient.ts`. Остальные компоненты знают только
его интерфейс, их трогать не нужно. После подключения `mockKnowledge.ts` можно удалить.

Места, помеченные `TODO(RAG)`, стоит доделать вместе с бэкендом. Главное из них — отправка
отзывов 👍/👎 на ответы.

## Форма записи

Бэкенда записи пока нет. Форма проверяет имя и телефон (`+998` и 9 цифр), копирует текст заявки
в буфер обмена и открывает Telegram клиники. Когда появится эндпоинт, замените тело `onSubmit`
в `components/Contacts.tsx` на `fetch()` — валидацию и разметку менять не нужно.

## Дизайн

Дизайн построен по Apple Human Interface Guidelines (скилл
[apple-design](https://github.com/dickwu/apple-design-skill)). На веб-сайт перенесены основы HIG, а не
нативные компоненты iOS:

- **Палитра** — кобальт и бирюза узбекской глазурованной майолики. Глазурь изразца и дентальный
  фарфор — по сути один материал. Контраст всех пар текст/фон посчитан по WCAG: основной текст
  17.4:1, вторичный 5.9:1, акцент 5.9:1. Бирюза (`--glaze`, 3.1:1) используется только для графики.
- **Стекло (Liquid Glass)** есть только на функциональном слое: на шапке и панели чата. Карточки
  контента плотные — стекло на контенте HIG считает ошибкой.
- **Доступность**: тёмная тема по системной настройке, откаты для «уменьшить прозрачность» и
  «увеличить контраст», уважение к «уменьшить движение». Минимальная цель нажатия — 44px,
  видимый фокус с клавиатуры, модальный чат с ловушкой фокуса и закрытием по `Esc`.
- **Движение** — один поставленный момент: изразцы узора один раз проявляются волной при загрузке.
